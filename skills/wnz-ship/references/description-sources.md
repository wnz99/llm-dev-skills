# Description policy sources

Consult when changing the description policy. Sources checked 2026-11-06.

- [Google: Writing good CL descriptions](https://google.github.io/eng-practices/review/developer/cl-descriptions.html): use a specific summary, explain what and why, and retain context for future readers.
- [GitHub: Helping others review your changes](https://docs.github.com/en/pull-requests/concepts/helping-others-review-your-changes): explain the problem, approach and result; guide reviewer attention, link related work, and self-check changes.

The default template combines those principles with explicit verification and
conditional risk information. Repository templates take precedence; the source
guides do not prescribe these exact headings. Language rules adapt the WNZ
writing skill's language and register guidance without requiring that package.
