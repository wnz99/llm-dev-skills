## Feature development flow

In a Git repository, when the user starts discussing a feature, fix, refactor or other change larger than a small direct edit, or resumes or asks about an existing development flow, read `{{WORKFLOW_FILE}}` in full before replying and follow it. Skip the read while its text is still in context; after context compaction, read it again when the trigger recurs. Skip it when the primary worktree has `.agents/feature-flow/WORKFLOW.md`, or the repository's `CLAUDE.local.md` import or `.codex/config.toml` developer instructions point to a repository-local feature-flow workflow; follow that one instead, and report any linked worktree that lacks its local loader. Repository policy and explicit user instructions take precedence.
