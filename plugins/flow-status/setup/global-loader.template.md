## Feature development flow

In a Git repository, when the user starts discussing a feature, fix, refactor or other change larger than a small direct edit, read `{{WORKFLOW_FILE}}` in full before replying and follow it. Skip the read while its text is still in context; after context compaction, read it again when the trigger recurs. Skip it when a repository-local flow is already loaded. Repository policy and explicit user instructions take precedence.
