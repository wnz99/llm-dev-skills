# Set up the standard development flow

Paste this exact prompt into Claude Code or Codex. For a local install, run it from the target repository. Replace `BUNDLE_ROOT` with the absolute folder containing this file's parent directory, and `MODE` with `global` or `local`; leave `MODE` in place to be asked. The setup agent discovers repository-specific choices; this prompt does not start a feature or approve a plan.

```text
Set up my personal standard development flow for both Claude Code and Codex in MODE install mode, using BUNDLE_ROOT/setup/PROCEDURE.md. If MODE is not global or local, ask me which mode to use before editing.

Read the procedure, bundled WORKFLOW.template.md, FLOW.example.json, STATE.template.md and the loader templates for the chosen mode before editing. Inspect the shared skills and, in local mode, the repository instructions, existing local client configuration and Git/worktree layout; in global mode, inspect each client's global instructions file. Preserve existing owners, instructions, credentials, hooks and unrelated edits.

Use one private workflow file shared by both clients (under ~/.agents/feature-flow/ in global mode), primary-worktree private drafts, the bundled schema-1 FLOW.json contract and the single herdr.flow-status plugin. Adapt paths and existing repository policies; in local mode, ask about genuinely unresolved integration branch or merge-policy choices; in global mode, ask once for the fallback branch and merge choices the procedure names. Do not copy machine- or project-specific defaults from examples. Resolve required skills through host discovery and check their declared dependencies. Install missing dependencies from their declared canonical sources when authorized; otherwise report the exact missing dependency and stop dependent setup.

Support ordinary local flows without a Linear issue or external ticket. Schema 1's historical ticket key holds a stable local flow ID such as cache-cleanup; linear_id may be omitted or null, and prs may be empty. Never infer a Linear association from a local ID, folder, title or branch. Explain this authoring contract without creating a real draft during setup.

Preserve the executor's canonical ledger and detailed reports under its host-discovered runtime contract. Required executor evidence may live outside the draft folder in an approved ignored location or external scratch path. The coordinator writes only supported summaries and evidence pointers into schema-1 FLOW.json; the dashboard reads that projection. Never inject unsupported canonical fields or infer executor gate approval from FLOW.json or GSD. Missing canonical artifacts block dependent execution on resume. Do not create executor artifacts during setup.

In local mode, make local-only changes ignored through Git's shared info/exclude and merge Claude and Codex loaders without replacing existing configuration. In global mode, merge one managed trigger block into each client's global instructions without replacing symlinks or other content. Do not add agents, skills, secrets or plugin source copies inside any repository. GSD is optional: report whether each client has it, do not install it, and rely on the workflow's tracking-record fallback when it is missing. Do not register a task or dispatch a planner/executor during setup.

Verify both clients' loaders or triggers resolve the same workflow, all paths are stable, required skills are discoverable and the bundled example passes the validator; in local mode also verify Codex TOML parses and private files are ignored. Record which checks ran and what remains unavailable. Do not fabricate approvals, create a live FLOW.json, start formal planning, commit, push, merge, deploy or run paid jobs as part of setup. Open the dashboard only if I request it, after verifying the live destination pane.
```
